# AGENT LEARNED RULES & PITFALLS

1. [Android Media3]: Always attach `Authorization: Bearer <token>` on `/v1/media/telegram/:file_id` streams; unauthenticated requests fail with 401/403.
2. [n8n Webhooks]: Use strictly the 14 canonical workflow IDs. Legacy IDs (e.g., BwP2..., S71...) are deprecated duplicates.
3. [EC2 Memory]: Local compilation causes Linux OOM killer. Never compile JVM artifacts locally; always push to GitHub Actions CI.
4. [Backend Env]: Batch 4 introduced mandatory `JWT_ISSUER` and `JWT_AUDIENCE` in server `.env`; container fails to start without them.
5. [Merge Order]: Backend CI checks out Android + Worker siblings at `SIBLING_REF=main`, so merge order MUST be Worker -> Android -> Backend; otherwise backend `main` runs cross-repo contract tests against stale code and goes red.
6. [Auth 503]: `AUTH_NOT_CONFIGURED` (HTTP 503) means `SUPABASE_ANON_KEY` is empty in container env — NOT a stale build. Correct endpoint is `/api/v1/auth/login` (`/v1/auth/login` returns 404). Login uses the Manager project (`icypjilkcqylgbpmkyes`), not the anime data project. New-format `sb_publishable_...` keys work in `SUPABASE_ANON_KEY`; after any `.env` change a `--force-recreate` is required (restart alone does not reload env_file).
7. [Runtime]: The 2026-11-15 live audit confirmed `anime_tenants` (2), `anime_tenant_members` (2), and `quota_usage` (7) now exist; earlier 500s from missing tenant tables are resolved. Re-check platform tables separately before assuming all of migration 005/006 is present.
8. [Runtime]: `/api/v1/auth/logout` revokes the refresh token (subsequent refresh = 401) but the access token stays valid until `exp` (~1h) because validation is stateless — client must clear the token locally on logout.
9. [Migrations]: Anime project is missing `003` object `project_prompt_associations`, all of `005` (`anime_tenants`, `anime_tenant_members`, `anime_platform_settings`) and all of `006` (`anime_platform_leases`, `anime_platform_pool_capacity`, `anime_platform_queue`, `anime_platform_usage`) → owner/pool endpoints return 500. Run migration audit before demo.
10. [CI]: GitHub Actions `workflow_dispatch` calls on this account end in `startup_failure` and push runs can stay queued for an hour (suspect Actions minutes/quota) — do not treat queued as passed; verify `conclusion=success`.
11. [Migrations]: Apply order 003 -> 004 -> 005 -> 006 with `psql -v ON_ERROR_STOP=1 -1`. Direct DB host `db.<ref>.supabase.co` is IPv6-only and unreachable from EC2; use pooler `aws-0-ap-south-1.pooler.supabase.com:5432` with user `postgres.<ref>`. Migration 004 defines `redact_sensitive_payload*` functions whose absence caused `OutboxDispatcher ... Expired payload redaction failed`.
12. [CI]: Worker failure at `ee47fdc` was the `actions/upload-artifact` step (pytest passed, XML generated locally) — treat as infra flake, not code. `workflow_dispatch`/rerun on this repo can return `startup_failure` with zero jobs, which is GitHub-side, not test-side.
13. [Workspace]: Login response fills `workspace_id=default-workspace` from `normalizeSession`, but `/api/v1/auth/me` returns `workspaceId: ""` for users without a Supabase `workspace_id` claim — client must not rely on `/me` for workspace scoping.
14. [Backend Deploy]: `auto_fix_and_test.sh` starts the container on the default bridge, but the live container must be on `--network ec2-user_default` (n8n DNS `http://n8n:5678`). Recreate with: `sudo docker build -t anime-backend:<sha> . && sudo docker rm -f ai-backend && sudo docker run -d --name ai-backend --restart unless-stopped --network ec2-user_default --network-alias backend --env-file .env -p 127.0.0.1:3000:3000 anime-backend:<sha>`. The `backend` alias is mandatory because canonical workflows fall back to `http://backend:3000` and n8n has no `ANIME_BACKEND_URL` override; recreating without it causes `getaddrinfo ENOTFOUND backend`.
15. [Compose Drawer]: `clickable` on drawer section header Rows (collapse/expand) did not toggle on real devices and silently blocked all Story/Production/Owner navigation. Keep drawer sections always expanded; never gate navigation behind a custom expand state.
16. [Project Delete]: All project-scoped child tables use `ON DELETE CASCADE` (only `documents`, `quota_logs`, platform lease/queue/usage use `SET NULL`), so `DELETE /v1/anime/projects/:id` is safe as a hard delete. Deleting twice returns 403 from `requireProjectRole`, not 404.

17. [n8n]: n8n v2 uses a `$node` DataProxy where ANY property access (`$node.name`) resolves via node-name lookup -> throws `ExpressionError: Referenced node doesn't exist` for nodes not named exactly like the property. Use static literals for callback ids (`+ ':completed:' + 'SUCCESS'`) and per-node env models for LLM (`$env.GROQ_MODEL` / `$env.GEMINI_MODEL`). Live workflow PUT via `PUT /api/v1/workflows/{id}` requires body keys beyond read-only fields; sending pre-fetched workflow JSON works when read-only fields (id/active/createdAt/...) are stripped.
18. [Backend Routes]: New route plugins must be registered in `registerAnimeRoutes`; route tests that import the handler directly can pass even when production returns 404. Verify with `app.hasRoute(...)` and a live unauthenticated request (expect 401, not 404).
19. [Migrations]: Migration 007 must drop both named unique constraints and the standalone unique indexes `uq_episodes_proj_epno` and `uq_clips_proj_ep_scene`; otherwise S1E1/S2E1 still cannot coexist. Every clip/episode/state/scene `on_conflict` key must include `season_no` after 007. `pg_dump` 15 cannot dump the Postgres 17.6 server; run `postgres:17-alpine pg_dump` via Docker.
20. [n8n API]: Workflow updates use `PUT /api/v1/workflows/{id}`, not PATCH (PATCH returns 405). Deactivate, send only `name`/`nodes`/`connections`/`settings`, then activate. Verify the live node hashes against repo and that `active=true`.
21. [Creative Prompts]: `projects.genre` is authoritative when non-empty; `story_bible.genre` is only a fallback. Merging both appends stale bible genres and breaks the expected project-selected order. The same fallback rule must be used by both `buildProjectCreativeContext` and `genreDisplayListForProject`.
22. [Migration 008]: The live `user_system_prompts_visual_medium_check` predated dynamic mediums and only allowed `ANIME`/`REAL_HUMAN`; custom `MANHWA` prompt inserts fail until 008 is applied. Its rollback is lossy if any non-legacy medium exists.
23. [Supabase Env Split]: `SUPABASE_URL`/`SUPABASE_SERVICE_ROLE_KEY` point at the Manager project, while anime data lives behind `ANIME_SUPABASE_URL`/`ANIME_SUPABASE_SERVICE_ROLE_KEY`. Querying `kaggle_sessions`, `episodes`, or prompt tables with the non-ANIME pair returns `PGRST205` even though the anime tables exist.
24. [WF-03 GPU Tunnel]: A `kaggle_sessions` row can remain `active` with a dead `trycloudflare.com` endpoint indefinitely (current row last updated 2026-09-30). Probe the endpoint before trusting it. Restarting requires Kaggle credentials; no live user infrastructure config currently holds them.
25. [Android Verification]: This Termux host has no `adb`/emulator. APK runtime checks against the backend cannot be completed here without an external device or emulator.
26. [BYOK]: Workflow gateway LLM calls now prefer the command user's decrypted `user_infrastructure[provider].api_key` and fall back to the platform env key only when absent. n8n still hardcodes `groq`/`gemini` provider names, so BYOK works for those providers only.
27. [Kaggle Security]: Never embed the anime service-role key in a user-owned Kaggle notebook. The worker now receives only a 6-hour HMAC `gpu_session` token and registers via `POST /v1/anime/internal/worker/session`; endpoints are limited to `*.trycloudflare.com`/`*.loca.lt` to reduce SSRF. Direct clip checkpoint writes were removed; n8n remains the writer.
28. [Kaggle Sessions]: After migration 009, non-system gateway reads of `kaggle_sessions` are forced to `user_id=eq.<command user>`. Old rows with `user_id IS NULL` become invisible, so the stale shared `kaggle_story_engine` row cannot be reused; the user must save Kaggle credentials and let `ensureKaggleWorkerForUser` create a per-user row.
29. [Migration 009]: It is additive but required before deploying the per-user session code: `ADD COLUMN user_id text`, `tenant_id uuid`, drop the old `session_name` unique constraint, then create the unique `(user_id, session_name)` index. `user_id` is text to match `api_commands.user_id`, not UUID.
30. [Outbox Lease]: The live DB was missing `outbox_events.processing_started_at` even though the code assumes it. Supabase update errors were ignored, so `markDispatched` never cleared events; the `recoverStaleProcessing` fallback reset them every tick and re-dispatched the same terminal commands forever. Symptom: huge `attempts`, `last_error='Recovered stale processing lease'`, thousands of duplicate n8n callbacks, high log ingestion/egress. Apply the 002 column/function, archive terminal stuck events, and fail closed on outbox transition errors. Migration 010 now performs lease recovery and `attempts >= 5` dead-lettering inside `claim_outbox_batch`.
31. [Workers]: `registerAnimeRoutes` now calls `startRole()` and honors `ANIME_PROCESS_ROLE`; poll defaults are 10s. A leftover `test-backend` container previously polled the same production outbox and mounted the prod `.env`; it has been removed. Never leave a second backend container running against the live DB.
32. [System Gateway]: `ANIME_WORKFLOW_SYSTEM_TOKEN` must be identical in backend `.env` and n8n compose env. It is now set; system gateway smoke returns 200 and WF-10/storywf13 succeed. Missing token returns 500 `Workflow gateway token is not configured`.
33. [Redaction]: `redact_expired_payloads` runs as a PostgREST/service-role RPC with an 8s statement timeout. A 500-row batch can exceed it; use <=100 rows and a `payload_redacted_at` marker so each row is processed once. The outbox/app triggers already redact on write; the TTL function is a backstop.
34. [Security Grants]: Supabase `anon`/`authenticated` had table grants and EXECUTE on sensitive SECURITY DEFINER functions even where RLS denied rows. Migration 010 revokes those grants and enables RLS on `kaggle_sessions`/`story_state`; backend/n8n use `service_role` only.
35. [DB Password Rotation]: Supabase pooler user `postgres.<ref>` cannot run `ALTER ROLE postgres PASSWORD ...`; it returns `permission denied to alter role / Only superusers can alter privileged roles`. Rotate via the Supabase dashboard (Project Settings -> Database -> Reset password) or Management API, not psql. The exposed old password remains valid until that dashboard action.
36. [n8n Upgrade]: Recreating `n8nio/n8n:latest` (2.43.7) preserved workflows and active flags in the `n8n_data` volume. Verify active workflows and post-recreate executions; `sqlite3` CLI is absent from the image, but host `python3` can read `/var/lib/docker/volumes/n8n_data/_data/database.sqlite` read-only.
37. [Tenant Gateway]: System-scope gateway writes must not use project injection; `project_id=system` causes `401 AUTH_INVALID: Write body project_id does not match the authenticated project.` Build writes with `!input.system && isProject ? injectProjectIntoBody(...) : validateWriteBody(body)`. BYOD routing is fail-closed: global catalogs and `kaggle_sessions` stay central, project reads/writes resolve through `anime_tenant_project_index`, and system GET/PATCH/POST fan out across central plus active BYOD planes. The tenant SQL translator supports `eq/neq/gt/gte/lt/lte/like/ilike/is/in`, `and`/`or`, `order`, `limit`, and `offset`; reject `not`, unbounded updates, and system offsets.
38. [Tenant Schema]: Tenant provisioning must create every table the gateway allows, not only `projects`. `tenantSchema.ts` is the source of truth: 30 data tables plus `schema_migrations` version 2, season-aware unique indexes, and project indexes. Use `CREATE ... IF NOT EXISTS` and `ALTER ... ADD COLUMN IF NOT EXISTS` so legacy projects-only databases upgrade in place. Data migration copies all project tables except transient `pending_actions`; verify per-table row counts and never copy in-flight actions. Rollback only re-points the index and must reject after the 7-day central copy window.
39. [Supabase BYOD]: Direct `db.<ref>.supabase.co` hosts resolve to IPv6-only addresses; EC2 has no IPv6 route, so backend/worker connections must use the project pooler host (for example `aws-0-ap-northeast-1.pooler.supabase.com`) with username `postgres.<ref>`. Also, `pg`/`pg-connection-string` may treat `sslmode=require` as `verify-full` and override an explicit `ssl` object, causing `self-signed certificate in certificate chain` against Supabase. Strip `sslmode` from the client DSN and pass explicit TLS options (`rejectUnauthorized: false` for `require`); use `tenantClientConnection()` for every tenant client. This applies to **both** `tenantDatabase.service` and `workflowGateway.tenantDb.defaultClientFactory`; fixing only the connect path leaves the n8n gateway broken with `Tenant database request failed`.
40. [Central DB Ref]: Verify Supabase project refs by DNS before use. The live central anime database ref is `lqdjlcfczjottagobega` (`db.lqdjlcfczjottagobega.supabase.co`); `aws-0-ap-south-1.pooler.supabase.com` works and `aws-1-ap-south-1` fails with tenant/user not found. The older `lqdjlcfczoyttagobega` spelling does not resolve.
41. [BYOD Tenancy]: A user needs an active `anime_tenant_members` row before tenant/BYOD routes work. Creating a tenant through `POST /v1/anime/tenants` creates the owner membership and is safer than direct SQL. Test-account tenant `f91f5074-08c0-4f47-925c-8ad1ae7a5fa1` then passed connect, provision, health, cutover, rollback, and re-migrate; the smoke project is `d946a6a6-02e3-45b4-9a88-61674a186306`.
42. [BYOD-First Gap]: `createProjectSynchronous` still inserts into central `projects` and `listProjects` still reads central. BYOD-first users therefore do **not** write directly to their database on project creation; they need an explicit per-project migration. Do not claim BYOD-first until creation and list routing are tenant-aware.
43. [Context Budget]: Run one OpenCode session per phase/wave and resume with "ledger se continue karo". A 190-step session reaches 150K+ of a 200K window even when most tokens are cache reads. Keep tool output narrow (`grep -n`, `sed -n` ranges, CI failure lines only), never paste full files, logs or screenshots into chat, and do not re-scan the repo; read the 32-line ledger plus only the task-specific files. Cache reads lower cost but do not free context, so start a fresh session after each deploy/APK wave.
