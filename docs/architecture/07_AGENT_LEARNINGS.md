# AGENT LEARNED RULES & PITFALLS

1. [Android Media3]: Always attach `Authorization: Bearer <token>` on `/v1/media/telegram/:file_id` streams; unauthenticated requests fail with 401/403.
2. [n8n Webhooks]: Use strictly the 14 canonical workflow IDs. Legacy IDs (e.g., BwP2..., S71...) are deprecated duplicates.
3. [EC2 Memory]: Local compilation causes Linux OOM killer. Never compile JVM artifacts locally; always push to GitHub Actions CI.
4. [Backend Env]: Batch 4 introduced mandatory `JWT_ISSUER` and `JWT_AUDIENCE` in server `.env`; container fails to start without them.
5. [Merge Order]: Backend CI checks out Android + Worker siblings at `SIBLING_REF=main`, so merge order MUST be Worker -> Android -> Backend; otherwise backend `main` runs cross-repo contract tests against stale code and goes red.
6. [Auth 503]: `AUTH_NOT_CONFIGURED` (HTTP 503) means `SUPABASE_ANON_KEY` is empty in container env — NOT a stale build. Correct endpoint is `/api/v1/auth/login` (`/v1/auth/login` returns 404). Login uses the Manager project (`icypjilkcqylgbpmkyes`), not the anime data project. New-format `sb_publishable_...` keys work in `SUPABASE_ANON_KEY`; after any `.env` change a `--force-recreate` is required (restart alone does not reload env_file).
7. [Runtime]: `/v1/anime/owner/quota` and `/v1/anime/owner/tenants` return 500 `Tenant membership lookup failed.` because `supabase/migrations/005_batch4_tenant_platform.sql` was never applied to the anime project (`anime_tenants` / `anime_tenant_members` tables absent).
8. [Runtime]: `/api/v1/auth/logout` revokes the refresh token (subsequent refresh = 401) but the access token stays valid until `exp` (~1h) because validation is stateless — client must clear the token locally on logout.
9. [Migrations]: Anime project is missing `003` object `project_prompt_associations`, all of `005` (`anime_tenants`, `anime_tenant_members`, `anime_platform_settings`) and all of `006` (`anime_platform_leases`, `anime_platform_pool_capacity`, `anime_platform_queue`, `anime_platform_usage`) → owner/pool endpoints return 500. Run migration audit before demo.
10. [CI]: GitHub Actions `workflow_dispatch` calls on this account end in `startup_failure` and push runs can stay queued for an hour (suspect Actions minutes/quota) — do not treat queued as passed; verify `conclusion=success`.
11. [Migrations]: Apply order 003 -> 004 -> 005 -> 006 with `psql -v ON_ERROR_STOP=1 -1`. Direct DB host `db.<ref>.supabase.co` is IPv6-only and unreachable from EC2; use pooler `aws-0-ap-south-1.pooler.supabase.com:5432` with user `postgres.<ref>`. Migration 004 defines `redact_sensitive_payload*` functions whose absence caused `OutboxDispatcher ... Expired payload redaction failed`.
12. [CI]: Worker failure at `ee47fdc` was the `actions/upload-artifact` step (pytest passed, XML generated locally) — treat as infra flake, not code. `workflow_dispatch`/rerun on this repo can return `startup_failure` with zero jobs, which is GitHub-side, not test-side.
13. [Workspace]: Login response fills `workspace_id=default-workspace` from `normalizeSession`, but `/api/v1/auth/me` returns `workspaceId: ""` for users without a Supabase `workspace_id` claim — client must not rely on `/me` for workspace scoping.
14. [Backend Deploy]: `auto_fix_and_test.sh` starts the container on the default bridge, but the live container must be on `--network ec2-user_default` (n8n DNS `http://n8n:5678`). Recreate with: `sudo docker build -t ec2-user-backend . && sudo docker rm -f ai-backend && sudo docker run -d --name ai-backend --restart unless-stopped --network ec2-user_default --env-file .env -p 127.0.0.1:3000:3000 ec2-user-backend`.
15. [Compose Drawer]: `clickable` on drawer section header Rows (collapse/expand) did not toggle on real devices and silently blocked all Story/Production/Owner navigation. Keep drawer sections always expanded; never gate navigation behind a custom expand state.
16. [Project Delete]: All project-scoped child tables use `ON DELETE CASCADE` (only `documents`, `quota_logs`, platform lease/queue/usage use `SET NULL`), so `DELETE /v1/anime/projects/:id` is safe as a hard delete. Deleting twice returns 403 from `requireProjectRole`, not 404.

17. [n8n]: n8n v2 uses a `$node` DataProxy where ANY property access (`$node.name`) resolves via node-name lookup -> throws `ExpressionError: Referenced node doesn't exist` for nodes not named exactly like the property. Use static literals for callback ids (`+ ':completed:' + 'SUCCESS'`) and per-node env models for LLM (`$env.GROQ_MODEL` / `$env.GEMINI_MODEL`). Live workflow PUT via `PUT /api/v1/workflows/{id}` requires body keys beyond read-only fields; sending pre-fetched workflow JSON works when read-only fields (id/active/createdAt/...) are stripped.
